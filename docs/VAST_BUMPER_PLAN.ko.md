# Vast.ai 기반 범퍼 손상 합성데이터 개발 기획서

작성일: 2026-09-09

## 1. 목적과 현재 상태

공개 GitHub 저장소를 임대한 Vast.ai 서버의 Jupyter에서 clone하여, 범퍼 정면 이미지로 기본 3D 부품을 만들고 찌그러짐·찍힘·긁힘을 추가한 RGB 이미지와 YOLO 라벨을 생성한다.

- 기존 low VRAM 테스트 완료. 사용자 보고상 RTX 4090에서 VRAM 부족 발생.
- 다음 테스트는 Vast.ai에서 임대한 RTX 5090 서버에서 진행한다.
- 5090 전용 노트북 배포가 목적이 아니다. 저장소 전체를 clone하여 환경 준비, 설정 변경, 실행, 미리보기, 데이터 내보내기를 수행한다.
- 이 문서는 제공된 소스를 분석한 구현 기획이다. GPU 추론, 의존성 설치, 범퍼 생성 개선, 손상 생성, YOLO 학습은 아직 수행하지 않았다.
- 기획 당시 범퍼 이미지와 기존 OOM 로그는 제공되지 않았다. 이후 범퍼 사진을 `assets/images/bumper.jpg`에 추가했다. 자동차 전체가 생성되는 원인은 미확정이다.

위 구조는 계획이며 현재 구현된 파일 목록이 아니다.

사용 순서: clone → 호환성 점검 → 설치 → Jupyter 커널 연결 → 모델 준비 → 범퍼 생성 → 검수 → 손상·렌더 → 데이터 다운로드.

- notebook에는 업무 순서와 설정을 두고 실제 연산은 모듈/CLI로 실행한다.
- clone URL은 공개 저장소가 정해지면 안내에 반영한다. 현재 GitHub 저장소를 만들거나 게시하지 않았다.
- 새 환경에서 필요한 Python·PyTorch·CUDA 조합과 CUDA 확장 연산을 실제 5090에서 검증하고 그 결과로 버전을 고정한다. 큰 VRAM만으로 패키지 호환성이 확보되었다고 판단하지 않는다.
- 모델 다운로드·컴파일·추론·GLB 변환 시간을 각각 기록한다.
- 생성, 렌더링, 보정, 학습은 별도 프로세스로 분리하여 불필요한 동시 GPU 점유를 방지한다.
- 재실행은 설정 해시·모델 버전·입력 해시가 같은 완료 결과를 재사용하며 미완료 결과를 성공으로 처리하지 않는다.
- 공개 대상은 코드와 공개 가능한 예제다. 회사 이미지, 모델 가중치, 결과, 캐시, 토큰과 notebook 실행 출력은 제외한다. 현재 `.gitignore`는 이 범위를 충분히 처리하지 않으므로 보완한다.

## 4. 모델 다운로드와 인증

확인된 직접 의존성은 Pixal3D, MoGe, DINOv3 이미지 특징 추출기, BiRefNet 계열 배경 제거, NAF다. pipeline 설정 및 외부 저장소에서 추가 의존성이 내려오므로 정적 목록만으로 다운로드 완료를 선언하지 않는다.

- 모델마다 저장소 ID, revision, 캐시 경로, 접근 가능 여부를 기록한다.
- `HF_TOKEN` 환경변수 또는 숨김 입력을 지원하며 토큰은 notebook 출력·로그·설정·압축파일에 저장하지 않는다.
- 로그인 실패, 접근 승인 필요, 파일 없음, 네트워크 실패, 디스크 부족, CUDA 오류를 구분한다.
- 원격 코드·가중치의 revision을 함께 고정한다. NAF의 Torch Hub 캐시도 별도로 관리한다.
- `background_mode=auto|provided_mask`를 추가한다. provided_mask에서는 마스크를 검증한 뒤 배경 제거 모델 생성·다운로드·추론을 모두 생략하도록 초기화 구조를 수정한다.
- 마스크 적용 전후 이미지와 정사각 크롭 결과를 저장하여 범퍼 외곽과 구멍이 보존되는지 확인한다.

## 5. 범퍼 부품 생성 기준과 한계 대응

입력에 없는 차체·바퀴·유리·차량 전체가 추가된 결과는 부품 생성 실패다. 정면에서 범퍼처럼 보이는 것만으로 통과시키지 않는다.

초기 범위는 정면 및 검수된 제한적 사선 시점이다. 정면 사진으로 보이지 않는 뒷면·장착부를 정확하게 복원했다고 취급하지 않는다.

실험 순서:

1. 원본, 배경 제거 마스크, 실제 모델 입력, 카메라 추정을 확인한다.
2. low VRAM 1024 / 표준 1024 / 표준 1536을 동일 입력·시드로 비교한다. 기존 로그가 완전하면 low VRAM 결과를 재사용한다.
3. 기준 카메라·크롭을 고정하여 steps와 guidance를 하나씩 바꾼다. 카메라 보정은 별도 실험으로 구분한다.
4. 자동으로 생성 단계별 VRAM·시간·OOM 위치를 기록하고, 실패 후 해상도나 모드를 조용히 변경하지 않는다.
5. 정면 실루엣 비교, 기본 무채색 렌더, 회전 영상으로 부품 범위를 검수한다. 단일 실루엣 점수만으로 부품 의미를 판정하지 않는다.
6. 설정 조정으로 자동차 전체 생성이 계속되면 추가 실측 시점 사진, 검수된 범퍼 메시/CAD 등을 기본 자산으로 사용하는 경로를 마련한다. 무제한 파라미터 탐색으로 해결을 약속하지 않는다.

원본 범퍼와 기본 메시의 기존 손상·가짜 긁힘·생성 오류도 검수한다. 라벨 없는 가짜 손상은 학습데이터에 포함하지 않는다.

## 6. 파라미터와 GLB·텍스처 평가

- 입력 이미지 크기, 생성 해상도, 출력 텍스처 크기를 구분한다.
- 첫 생성 실험은 원본 기준값, 다음은 단계별 steps 약 1.5배/2배와 guidance 주변값으로 한 항목씩 비교한다. 지원 범위와 비용에 따라 실제 목록을 확정한다.
- 동일 생성 결과의 중간 표현을 저장하여 2048/4096 텍스처, 10만/30만/100만 목표 면 수, remesh, PNG/WebP를 재출력한다. 원본 고밀도 자산은 손상 작업용으로 별도 보존한다.
- 손상 변형에 필요한 국소 메시 밀도를 검수한다. 보기용 단순화 자산을 그대로 변형 원본으로 쓰지 않는다.
- GLB 구조 검사와 Blender/웹 뷰어 실제 표시 검사를 분리한다.
- 텍스처 원본, UV, Base Color 무조명 렌더, 고정 조명 PBR 렌더를 비교해 생성·베이킹·표시 오류를 구분한다.
- 전처리 변환과 카메라, GLB export 좌표 변환을 저장해 RGB와 마스크 정합성을 유지한다.
- 입력 사진에는 조명·반사가 포함되므로 Base Color와 직접 픽셀 일치를 요구하지 않는다. 정렬된 전경 영역의 실루엣·특징 위치·색상 차이와 시각 검수를 함께 사용한다.

## 7. 손상 생성

찌그러짐은 넓은 표면 함몰·굴곡, 찍힘은 국소 함몰(도장 손상 포함 여부 미확정), 긁힘은 길쭉한 도장·거칠기·노멀 변화로 초기 정의한다.

| 손상 | 표현 | 파라미터 |
|---|---|---|
| 찌그러짐 | 실제 메시 변형으로 반사·그림자 변화 생성 | 표면 위치, 반경, 깊이, 비대칭, 방향, 강도 |
| 찍힘 | 작은 함몰과 선택적 도장 손실 | 위치, 크기, 깊이, 경계 형태, 도장 손실 |
| 긁힘 | 곡면 경로를 따라 색·거칠기·노멀 조정, 필요 시 얕은 홈 | 길이, 폭, 방향, 군집, 깊이 |

- 손상 가능한 표면 영역을 지정한다. 구멍·뒷면·빈 공간·잘못 생성된 형상은 제외한다.
- 물리 단위 치수가 없으면 깊이를 mm 단위의 실제 손상으로 주장하지 않고 자산 크기 대비 상대값으로 기록한다.
- 각 손상에 instance ID와 표면 영역을 부여한다. 겹침·복합 손상의 라벨 정책을 명시한다.
- 변형 후 자기 관통, 비정상 노멀, 메시 파손을 검수한다.
- 최소 시제품은 검수된 범퍼 1개에 손상 3종을 각각 만들고 강도별 RGB/마스크를 비교한다. 사실감과 라벨을 검수한 후 배치 생성을 확장한다.

## 8. 렌더링과 자동 라벨

검수된 기본 범퍼와 손상 정보를 Blender 등의 동일 장면에 적용하여 RGB, 손상별 가시 영역 마스크, 깊이·노멀, 카메라 정보를 출력한다. 렌더러의 정확한 버전과 GPU 지원은 구현 시 고정한다.

- RGB와 마스크는 같은 메시·카메라·변형을 사용한다. 조명 영향을 받지 않는 손상 ID 출력을 별도 구성한다.
- 최종 이미지의 가려짐, 화면 밖 잘림, 해상도 축소를 반영한 마스크에서 박스를 계산한다.
- 정상 이미지에는 손상 라벨을 부여하지 않는다.
- 손상 표면 영역과 손상으로 인한 그림자·반사는 구분한다. 변형 영향 반경을 그대로 가시 손상 정답으로 간주하지 않고 실제 라벨 정책에 맞게 범위를 조정한다.
- 최소 픽셀 크기·가시 비율·식별 가능성 기준은 실제 학습 해상도에서 정한다. 너무 작거나 보이지 않는 손상은 제거·재생성한다.
- 기준안은 YOLO 검출 라벨과 인스턴스 PNG 마스크 동시 저장이다. 세그멘테이션이 필요하면 마스크 원본에서 다각형을 만들고 가늘고 끊어진 긁힘의 손실을 검사한다.
- 이미지별 클래스·박스·마스크 겹침 미리보기와 라벨 범위 검사 결과를 저장한다.
- 촬영 조건은 실제 운영 환경에 맞춘다. 분리된 범퍼/장착된 범퍼, 조명, 거리, 배경은 사용자 확인이 필요하다.

## 9. Stable Diffusion 보정 범위

기본 자산의 외관 보정 또는 배경 변화에 우선 사용한다. 손상 생성 후 전체 RGB에 적용하는 보정은 별도 선택 실험으로 둔다.

- 메시를 고정하고 여러 시점의 구조 조건을 사용한 텍스처 보정은 투영, 가림 처리, UV 베이킹, 시점 간 일관성 검증이 별도로 필요하다.
- 색상·로고·무늬를 유지하고 조명 음영이 Base Color에 과도하게 고정되지 않는지 확인한다.
- 보정으로 생긴 가짜 손상은 기본 자산 검수에서 제거한다.
- 손상 생성 후 이미지 보정은 손상을 지우거나 추가할 수 있으므로 기존 라벨의 유효성을 가정하지 않는다. 검증되지 않은 보정 결과는 자동으로 학습셋에 넣지 않는다.

## 10. 실험 기록과 학습 효과

실험별로 GLB, 텍스처, RGB, 마스크, YOLO 라벨, 입력/모델/코드 식별자, 전체 설정, 시드, 시간, 단계별 VRAM, 오류를 저장한다.

- 동일 원본 범퍼·기본 메시에서 파생된 샘플은 같은 split에 둔다. 시드가 다르다고 독립 자산으로 간주하지 않는다.
- 실제 데이터도 동일 부품·차량·촬영 세션이 train/test에 섞이지 않도록 그룹으로 분리한다.
- 정상, 반사광, 이음새 등 오검출하기 쉬운 사례를 포함한다.
- 실제 손상 사진의 독립 평가셋에서 클래스별 precision/recall, mAP, 정상 이미지당 오검출을 확인한다.
- 실제 라벨 데이터가 있으면 동일 조건의 실제-only와 실제+합성 학습을 비교한다. 실제 평가셋이 없으면 합성 내부 평가만 가능하며 현장 개선을 주장하지 않는다.
- 초기 데이터량·클래스 비율·시간 예산은 소량 렌더의 실제 비용과 검수 결과로 확정한다.

## 11. 구현 순서와 완료 기준

| 순서 | 구현 묶음 | 완료 기준 |
|---|---|---|
| P0 | 설치·진단·모델 인증·공개 저장소 정리 | 새 Vast.ai clone 환경에서 설치 및 의존성 연산 점검, 토큰 미노출 |
| P1 | 설정형 추론·전처리 보존·출력 옵션·측정 | 범퍼 정면 입력으로 추론 로그, GLB, 전처리, 설정을 함께 저장 |
| P2 | 범퍼 범위·형상·텍스처 검수 | 검수된 부품 자산 확보 또는 실패 조건과 대체 경로 명시 |
| P3 | 손상 3종·RGB/마스크 동시 렌더 | 소량 예시의 손상 사실감과 라벨 일치 검수 |
| P4 | 배치 생성·YOLO 변환·데이터 검증 | 재시작 가능한 생성, 정상 포함, 그룹 split, 라벨 미리보기 |
| P5 | 선택적 SD 보정·학습 효과 분석 | 보정 라벨 정합성 및 실제 평가 결과 확보 |

검증은 설정/좌표 변환, 빈 마스크, 가림과 잘림의 라벨 계산, 손상과 무손상 사례 등 오류가 실제 데이터 품질에 영향을 주는 부분에 집중한다. GPU smoke test는 설치된 Vast.ai 환경에서 별도로 수행한다.

## 12. 남은 확인 사항

1. 현재 범퍼 원본 이미지와 자동차 전체로 생성된 결과, 4090 OOM 로그.
2. 실제 YOLO 입력이 분리된 범퍼인지 차량에 장착된 범퍼인지.
3. 검출 박스와 세그멘테이션 중 우선 과제. 기본 제안은 검출 + 원본 마스크 저장.
4. 찍힘의 정의, 실제 손상 사진·라벨 보유 여부, 입력 범퍼 종류와 수량.
5. 공개 저장소 이름/계정과 Vast.ai 작업 시간·예산. 게시할 파일 준비와 검증을 먼저 완료한다.
